# B站会员视频下载指南（最终版）

## 📌 问题说明

由于 Chrome 在 macOS 上使用钥匙串加密 Cookie，自动从浏览器提取 Cookie 在沙箱环境中不可靠。因此，**需要手动配置 B站 Cookie** 才能下载会员视频。

好消息是：只需要配置一次，Cookie 会持续生效（通常几个月）。

## ✅ 解决方案

本项目已内置强大的 Cookie 自动加载机制：
- 服务器端自动加载 `backend/bilibili_cookies.txt` 文件
- 前端无需传递 Cookie，直接下载即可
- 支持 Cookie 文件验证、浏览器回退等多种方式

## 🚀 配置步骤（只需一次）

### 方法 1：使用浏览器扩展导出 Cookie（推荐，最快）

这是最简单、最完整的方法，一次导出即可。

#### 步骤 1：安装浏览器扩展
1. 在 Chrome 中访问扩展商店
2. 搜索并安装 "Get cookies.txt LOCALLY" 扩展
   - 扩展地址：https://chrome.google.com/webstore/detail/get-cookiestxt-locally/cclechndkgdckloadeadgfjbghhaidln
3. 确保在 Chrome 中已经登录 B站 账号（且有会员权限）

#### 步骤 2：导出 Cookie
1. 在 Chrome 中访问 https://www.bilibili.com
2. 点击浏览器工具栏的 "Get cookies.txt LOCALLY" 扩展图标
3. 在弹出的窗口中，找到并选择 `.bilibili.com` 域名
4. 点击 "Export" 下载 `cookies.txt` 文件

#### 步骤 3：配置到项目
1. 打开终端，进入项目 backend 目录：
   ```bash
   cd backend
   ```
2. 运行配置工具：
   ```bash
   python setup_bilibili_cookies.py
   ```
3. 选择方法 1（导入文件），输入刚才导出的 `cookies.txt` 文件路径
4. 工具会验证 Cookie 并自动配置

#### 步骤 4：测试
工具会提示是否测试 Cookie，输入一个 B站会员视频 URL 即可测试。

### 方法 2：手动输入 Cookie 值（无需安装扩展）

如果您不想安装扩展，可以手动复制 Cookie 值。

#### 步骤 1：获取 Cookie 值
1. 在 Chrome 中访问 https://www.bilibili.com 并登录
2. 按 `F12` 打开开发者工具
3. 切换到 `Application` 标签
4. 左侧展开 `Storage` → `Cookies` → `https://www.bilibili.com`
5. 在右侧 Cookie 列表中找到以下值并复制：
   - **SESSDATA**（必需）
   - **bili_jct**（必需）
   - **DedeUserID**（必需）
   - **DedeUserID__ckMd5**（可选，建议提供）
   - **sid**（可选）

#### 步骤 2：配置到项目
1. 打开终端，进入 backend 目录：
   ```bash
   cd backend
   ```
2. 运行配置工具：
   ```bash
   python setup_bilibili_cookies.py
   ```
3. 选择方法 2（手动输入），依次粘贴刚才复制的 Cookie 值
4. 工具会自动生成 `bilibili_cookies.txt` 文件

#### 步骤 3：测试
同方法 1，可选测试。

## 📝 使用方法

配置完成后，使用方法非常简单：

### 方式 1：Web 界面（推荐）

1. 确保后端服务正在运行：
   ```bash
   cd backend
   python main.py
   ```

2. 确保前端正在运行：
   ```bash
   cd frontend
   npm run dev
   ```

3. 访问 http://localhost:5173

4. 输入 B站会员视频 URL，例如：
   ```
   https://www.bilibili.com/video/BV1xxxxxxx
   ```

5. 点击"解析视频"，选择格式，点击下载

**前端无需传递 Cookie，服务器会自动使用配置的 Cookie 文件！**

### 方式 2：Python 代码调用

```python
from downloader import VideoDownloader

downloader = VideoDownloader()

# 解析 B站会员视频
video_info = downloader.parse_video("https://www.bilibili.com/video/BV1xxxxxxx")

# 下载视频
result = downloader.download_video("https://www.bilibili.com/video/BV1xxxxxxx", "best")

# 获取直链

```

### 方式 3：API 调用

```bash
# 解析视频（前端无需传 cookies）
curl -X POST "http://localhost:8000/api/parse" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.bilibili.com/video/BV1xxxxxxx"}'

# 下载视频（前端无需传 cookies）
curl -X POST "http://localhost:8000/api/download" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.bilibili.com/video/BV1xxxxxxx", "format_id": "best"}'
```

## 🔧 高级配置

### 环境变量覆盖

您可以通过环境变量指定 Cookie 文件路径或直接传入 Cookie 字符串：

```bash
# 方法 1：指定自定义 Cookie 文件路径
export BILIBILI_COOKIES_FILE="/path/to/your/cookies.txt"

# 方法 2：直接传入 Cookie 字符串
export BILIBILI_COOKIES="SESSDATA=xxx; bili_jct=xxx; DedeUserID=xxx"

# 然后启动后端
cd backend
python main.py
```

### Cookie 文件格式

Cookie 文件采用标准的 Netscape 格式：

```
# Netscape HTTP Cookie File
# Generated by setup_bilibili_cookies.py
.bilibili.com	TRUE	/	TRUE	1900000000	SESSDATA	你的SESSDATA值
.bilibili.com	TRUE	/	TRUE	1900000000	bili_jct	你的bili_jct值
.bilibili.com	TRUE	/	TRUE	1900000000	DedeUserID	你的用户ID
.bilibili.com	TRUE	/	TRUE	1900000000	DedeUserID__ckMd5	你的用户ID哈希
.bilibili.com	TRUE	/	FALSE	1900000000	sid	你的会话ID
```

## ⚠️ 常见问题

### Q1: 为什么不能自动提取 Chrome Cookie？

**A:** Chrome 在 macOS 上使用钥匙串加密 Cookie，自动提取需要钥匙串访问权限。在非交互式环境（如沙箱）中，钥匙串访问可能失败。因此最可靠的方式是手动配置。

### Q2: Cookie 会过期吗？

**A:** 会的。B站的 SESSDATA 通常有几个月的有效期，但具体取决于您的账号和活动情况。如果下载失败，请重新配置 Cookie。

### Q3: 如何验证 Cookie 是否有效？

**A:** 运行 `python setup_bilibili_cookies.py` 后，工具会提供测试选项，输入一个 B站会员视频 URL 即可测试。

### Q4: Cookie 文件存放在哪里？

**A:** 默认存放在 `backend/bilibili_cookies.txt`。

### Q5: 是否支持其他浏览器？

**A:** 支持任何能导出 Netscape 格式 Cookie 文件的浏览器，包括 Safari、Firefox 等。导出后使用方法 1 导入即可。

### Q6: 下载会员视频时出现 HTTP 412 错误？

**A:** 这通常表示 Cookie 已过期或无效。请重新运行 `python setup_bilibili_cookies.py` 配置新的 Cookie。

### Q7: 我配置了 Cookie 但仍然无法下载会员视频？

**A:** 可能的原因：
1. Cookie 已过期 → 重新配置
2. 账号没有该视频的会员权限 → 检查账号状态
3. 视频链接错误 → 确认视频 URL 正确
4. 后端服务未重启 → 重启后端服务

## 🔒 安全提示
